# Schritt 1 – Projektideen dokumentieren

> **Ziel:** Mindestens sechs voneinander unterscheidbare Projektideen als einheitlich aufgebaute Word-Dokumente sammeln. Noch keine Projektauswahl.

| Merkmal           | Festlegung                                                                                       |
| ----------------- | ------------------------------------------------------------------------------------------------ |
| **Art**           | Individuelle Arbeit; anschliessend Einreichungsprüfung                                           |
| **Termin**        | Abgabefrist bis am **29.11.2026** um **18:00 Uhr**                                               |
| **Verantwortung** | Alle sechs Teammitglieder: mindestens je eine Idee; Projektkoordination: Vollständigkeitsprüfung |
| **Methode**       | Individuelles Brainwriting / divergente Ideenfindung                                             |
| **GitHub**        | Je eine zugewiesene Issue-Aufgabe pro Person; Kanban `01 – Vorstudie`                            |

## Warum dieser Schritt wichtig ist

Alle Teammitglieder sollen unabhängig voneinander Vorschläge erarbeiten können, ohne sich frühzeitig auf eine bestimmte technische Lösung festzulegen. Jede Idee wird in derselben Struktur beschrieben, damit ein fairer Vergleich möglich ist.

## Inhalt jeder Projektidee

1. **Ausgangslage und Motivation:** Welche Situation oder welcher Bedarf besteht?
2. **Problem oder Chance:** Was soll konkret verbessert oder ermöglicht werden?
3. **Projektidee:** Wie könnte ein System grundsätzlich helfen?
4. **Anwendungsszenarien:** Zwei kurze Beispiele nach dem Prinzip «Wenn …, dann …»; optional eine User Story.
5. **Zielgruppe und Nutzen:** Wer profitiert und wodurch?
6. **Zusammenspiel der Fachrichtungen:** Welche Hardware/Sensorik, Kommunikation, Infrastruktur und Software wären denkbar?
7. **Offene Fragen:** Was muss erst noch geprüft werden (Machbarkeit, Budget, Datenschutz, Sicherheit usw.)?

**Umfang:** Richtwert 1–2 A4-Seiten. Verständlicher Fliesstext statt Pflichtenheft, vollständiger Architektur oder endgültiger Komponentenwahl. Annahmen als Annahmen kennzeichnen; keine Kosten oder technischen Fakten erfinden.

## Ablauf

1. Vorlage unter [`../Templates/Projektidee_Vorlage.docx`](../Templates/Projektidee_Vorlage.docx) lesen (falls im Repository vorhanden) und für die endgültige Einreichung die Word-Vorlage verwenden.
2. Für KI-Unterstützung [`../Ideen/AGENTS.md`](../Ideen/AGENTS.md) verwenden. Der Agent erstellt **Text/Markdown**, nicht automatisch eine freigegebene Projektidee. Die Autorin oder der Autor prüft die Aussagen.
3. Text in die Word-Vorlage übertragen, als eigene `.docx` speichern und unter [`../Ideen/`](../Ideen/) ablegen. Beispiel: `Idee_01_Kurztitel.docx`.
4. Dokument im persönlichen GitHub-Issue verlinken; Issue zur Überprüfung in `Review` verschieben.
5. Projektkoordination prüft nur Vollständigkeit und Lesbarkeit, **nicht die Beliebtheit der Idee**. Danach `Done`.

## Ergebnis / Definition of Done

- [ ] Mindestens sechs unterschiedliche Ideen sind eingereicht.
- [ ] Alle Dokumente haben dieselben Abschnitte und sind in `Vorstudie/Ideen/` auffindbar.
- [ ] Zu jeder Einreichung existiert ein zugewiesenes und abgeschlossenes GitHub-Issue.
- [ ] Alle Ideen sind vor dem Auswahltreffen für das Team lesbar.
